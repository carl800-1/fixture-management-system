# 工装夹具管理程序（桌面版 / 独立 exe）

**v5.8.1 是一个打包好的桌面程序**（基于 Electron）。双击 `工装夹具管理程序.exe` 即可使用，**无需安装、无需联网、无需浏览器**，所有数据保存在本机文件里。

> 系统覆盖夹具从建档、出库、回库、送修、维修完成到报废的全生命周期管理，并支持二维码标签、扫码作业、流水追溯与数据备份。
>
> **v4.0.0 是一次 MAJOR 升级**：数据模型从「按编号的台账」改为 **「每套一条记录」的追踪模型** ——
> **夹具编号**（如 `DH40MC-921-001-001`，可重复、手动输入、主搜索键）与系统自动分配的
> **序号**（4 位纯数字、唯一、二维码内容、不参与模糊搜索）分离；**数量不再存储，而是按
> 「夹具编号 + 库位」实时派生**；「夹具 ↔ 产线 / 工位」改为夹具记录上的扁平关联字段。
> 升级细节见 `修改日志.md` 的 v4.0.0 条目；已知问题、待确认事项与环境限制见 `问题清单.md`。
>
> **v5.0.0 是一次 MAJOR 升级（破坏性重构：移除工位模型）**：
> ① **「工位」概念整体移除** —— `stations` 集合、夹具的 `fixtures.stations` 字段、工位 CRUD 表单、
> 工位相关校验（≥1 工位 / ≤10 工位 / 工位必须属于已选产线）、导入模板中的工位列、刷新产线配置时的工位面板**全部删除**；
> 夹具与产线改为**一层扁平关联**（`fixtures.lines`，≥1 条 ≤5 条）。
> ② **「产线示意图」（工位节点 SVG 图）整段删除** —— 产线配置页与产线使用页都不再有图，改为纯表格。
> ③ **「按夹具编号查询（数量与合计）」面板移除** —— 「夹具查询」页只保留下方多条件组合检索。
> ④ 夹具导入/导出模板 **22 列 → 17 列**（`夹具编号 / 名称 / 机种名称1~7 / 分类 / 库位 / 产线1~5 / 备注`），
> 旧版「产线」「工位」列仍可导入 —— 产线照常解析，**工位列被静默忽略**。
> ⑤ 产线配置导入模板 **6 列 → 4 列**（`线体 / 线体形态 / 夹具编号 / 备注`）。
> ⑥ 打开旧数据文件时 `migrate()` 会**自动清理** `data.stations` 与每条夹具的 `stations` 字段，无需手工处理。
> ⑦ 机种明细由「线体 → 工位 → 夹具」改为「**线体 → 夹具**」两级。
> ⚠️ 升级代价（不可回避）：**「某套夹具装在产线的哪个工位」这一信息不再被记录**。若将来需要，
> 只能作为新的可选字段重新引入；当前所有报表、导入导出、检索都**不再涉及工位**。

> **v5.7.1 是一次 PATCH 修复（出库/回库「出库错件」）**：
> 旧版点「提交出库 / 提交回库」的瞬间，会按数量框把候选列表**前 N 件**重新勾一遍，
> 把你手动勾选的夹具整片覆盖 —— 出库的、流水记录的都是列表最前面那几件，界面没有任何提示。
> 典型现场：选 G10SP5 + 「主轴-压头工装」、数量 3，本应出库 4169/4170/4171，
> 实际出的却是 4166/4167/4168（分属两个不同名称）。
> 现在改为**勾选是唯一数据源**：提交只校验、不改写勾选；数量框自动跟随勾选回填，
> 两者不一致时明确提示「已按勾选提交」。
> 同时修掉：扫码选中会清空此前勾选（连扫多件只剩最后一件）；
> 流水「夹具」列增加**实物编号副行**（4 位序号与 G10BP5-… 并排）；
> 移除出库页那个点了没反应的「📷 批量扫码出库」按钮。

> **v5.8.1 是一次 MINOR 升级（库位按「套」管理：同一工装号多套可分布在多个库位，不再误报异常）**：
> 原规则「一套工装一个库位，多套应同库位，不一致=异常」把**正常物理分布**误标为异常 ——
> 数据核对：库位不一致 218 组 / 800 条中，**166 组 / 623 条**是同一夹具多套散放不同库位（名称一致），
> 属正常存储。库位本是「套」的属性（单件追踪：一套只在一个库位），同一工装号的多套**可以**不同库位。
> 现「库位不一致」不再标红异常，异常工装页只保留名称不一致 / 编号格式异常 / 套号缺失三类；
> 「⚡ 统一库位」入口移除，改为「**库位分布**」信息展示（多套分布各库位及套数，便于快速找套）。

> **v5.7.0 是一次 MINOR 升级（新增「未导入明细」记录与导出）**：
> 导入完成后，结果窗口会**逐行列出本次没有进库的数据** —— 行号 / 夹具编号 / 名称 / 库位 / 未导入原因，
> 按行号升序，最多显示前 200 行；底部「⬇ 导出未导入明细 CSV」可拿到**全部明细**（`未导入明细_日期_时分.csv`）。
> 未导入原因分四类写明：**解析未通过**（名称为空 / 库位不合规 / 机种全空…）、**与库内记录完全一致**（选了跳过重复）、
> **产线未建档按选择跳过**、**落库失败**（附主进程返回的具体原因）。
> 顺带修掉一个黑盒：旧版落库失败只 `console.warn`，界面上只有一个「失败 N 条」的数字，用户根本查不到是哪几行。
> 整份表一行都导不进时同样可导出全部跳过明细。

## 二维码功能（离线）

系统已内置二维码**生成**（`qrcode-generator`）与**解码**（`jsQR`）库到 `js/vendor/`，**完全离线、无需联网**。

- **编码规范**：二维码只承载**序号**，内容就是**序号本身**（如 `1001`，纯 4 位数字，**无任何前缀**）。该 token 是**派生值**（由 `code` 现场计算），**不落库**，避免与编号不一致的脏数据；名称 / 夹具编号等由系统按编号实时查库补全（原因：纯 ASCII 扫描最稳、码更小、且改名不影响旧码）。扫码端仍兼容早前标签的 `SPMS1|<序号>` / `SPMS|<序号>` 前缀。
- **标签卡内容**：只打印 **夹具编号 + 夹具名称** 两项（v4.0.0 起移除机种与库位，让标签更简洁、字号更醒目）。取舍：码磨损后需重新打印（可在「夹具管理」里按编号查回后重印）。
- **生成标签**：「夹具管理」每行「二维码」可预览/下载单张 PNG；顶部「批量打印标签」可一次性生成全部在库夹具的标签（二维码 + 编号 / 名称 / 机种名称 / 库位文字），用系统打印到标签纸。
- **扫码作业**：「出库 / 回库」均提供扫码入口，识别后自动选中对应夹具，后续录入流程不变。
  - **上传图片识别**：对标签拍照后上传即可识别，**离线可用**，是 exe 内的主用方式。
  - **摄像头实时扫码**：受桌面环境安全上下文限制，exe 内默认隐藏摄像头入口、仅保留上传图片，不影响作业。

## 刷卡录入（v5.1.0 新增）

进出库的**人**不再手打姓名，改为**刷工牌**。系统新增「👤 人员卡库」维护「卡号 → 姓名」，刷卡时按卡号反查姓名填进流水。

### 适用位置（4 处 / 8 个刷卡位）

| 位置 | 刷卡位 | 说明 |
| --- | --- | --- |
| 🔼 出库管理（批量页） | **领用人** | 页面中部一个刷卡框，刷完即允许「确认出库」（v5.6.0 取消经办位） |
| 🔄 回库管理（批量页） | **退库人** | 同上，退库人 = 把夹具送回来的人 |
| 单件出库弹窗（卡片「出库」） | **领用人** | 弹窗内一个刷卡框 |
| 单件回库弹窗（卡片「回库」） | **退库人** | 弹窗内一个刷卡框 |

> **为什么是键盘输入而不是驱动**：USB 读卡器（HID 键盘模拟型）刷卡时就是「快速敲一串字符 + 回车」，
> 系统只需在刷卡框上监听回车。**不需要装驱动、不需要选 COM 口**，Windows 认成键盘即可用。

### 各字段的填写方式

| 字段 | 填写方式 | 手打可以吗 |
| --- | --- | --- |
| 领用人 / 退库人（**对方**） | 把工牌在读卡器上**刷一下**（光标需停在该框），卡号自动填入并回车确认，框右侧立刻显示**姓名** | ✅ 可以。光标在该框时**手工敲卡号 + 回车**，效果完全等同刷卡（读卡器坏了 / 远程指导时用） |
| 姓名 | **不录入、不手填** —— 系统按卡号从人员卡库反查后自动显示，只读 | ❌ 页面已无姓名输入框，只能通过卡号带入 |

刷卡成功后的显示：`✅ 李领用 · 车间`。刷失败会红字提示原因，**必须重新刷**。

### 校验规则（v5.6.0 单人版）

提交时校验，任一条不满足即拒绝提交并 `toast` 报错：

| # | 规则 | 不满足时的提示 |
| --- | --- | --- |
| 1 | **必须刷一个人**（领用人 / 退库人），为空即拒绝 | `请刷领用人的工牌（卡号不能为空）` |
| 2 | 卡号**必须在人员卡库登记过** | 「卡号 XXX 未登记，请先在「👤 人员卡库」登记」 |
| 3 | 卡片状态必须为**启用**（`active = true`） | 「卡号 XXX 已停用（张三），不能使用」 |

> **v5.6.0 已取消的两条**：① 不再要求第二个「经办人」；② 刷卡位**不再按角色设限**
> —— 历史「经办人」角色的老卡照常能刷领用/退库位，不必逐张改卡。
> 因此原「两位不能是同一张卡」的双人复核规则也一并失效（只剩一个人，无从比较）。

刷卡瞬间（不等提交）就会做 2~3 的**即时校验**并写徽标，所以问题当场可见；规则 1 在提交时兜底。

### 卡号归一化（一张卡只有一种身份）

比对前统一做归一化：**去掉所有空格（含全角空格）/ `-` / `_`，字母转大写**。

- 所以 `OP-0001`、`op 0001`、`OP_0001` **视为同一张卡**，登记录入时会互相判重。
- **落库与显示保留你录入的原样**（如 `OP-0001`），只有比对和**流水里的卡号快照**用归一化形式（`OP0001`），便于按卡追溯。
- 长度上限 64 字符；不允许 `|` 和逗号（会破坏 CSV 导入导出）。

### 人员卡库维护

- **建档**：卡号（光标停在卡号框时**直接刷卡即可**，回车不会提交表单，只做查重并跳到姓名框）→ 姓名 → 部门（可空）→ **角色** → 状态 → 备注。
- **角色**：`领用人` / `经办人（历史）` / `两者皆可`。**v5.6.0 起角色不再参与刷卡校验**，只作台账标注；
  历史数据里的 `operator` 角色原样保留，不影响使用。
- **停用 vs 删除**：**优先停用** —— 停用后该卡不能再刷，但历史流水、人员台账都还在；删除会连人一起消失（流水里的姓名/卡号快照仍在，不影响历史追溯）。离职一律停用。
- **批量导入**：表头 `卡号 | 姓名 | 部门 | 角色 | 状态 | 备注`（别名兼容 `工号`/`员工号`、`所属部门`、`权限`、`是否启用`）；角色可写 `领用人`/`经办人`/`两者皆可`（也认 `仓管`）；状态可写 `启用`/`停用`/`否`/`离职`。导入前必过预览，逐行显示可导入 / 跳过原因。
- **清空数据不会清人员卡库**：与产线、机种同属主数据。

### 流水里的痕迹

出库 / 回库流水记录 `partyCard`（归一化卡号）与领用人 / 退库人姓名快照。
`operator` / `operatorCard` 字段**保留但 v5.6.0 起新记录写空串** —— 历史流水的经办人仍在，可查可搜可导出。
**删人、改名、停用都不影响历史流水**，任何时候都能按卡号追到「谁在什么时候领了什么」。

> ⚠️ 升级后第一次用：如果人员卡库是空的（旧数据升级即如此），刷卡一定失败。请先去「👤 人员卡库」把
> 常用工牌登记一遍，或下载模板批量导入。

## 出入库「全选」一键批量（v5.5.0 新增）

出库页「可出库」与回库页「待回库」的**状态条右侧**各有一个「全选」开关。

| 场景 | 表现 |
| --- | --- |

| 有 N 条结果、尚未勾选 | 文案「全选 N 套」 |
| 点「全选」 | 结果区 N 套**全部勾上**（跨分组），分组头同步勾上；出库 / 回库**数量自动填 N**；已选摘要显示「已选 N 套」；开关高亮、文案「已全选 N 套」 |
| 手动取消其中一套 | 开关转**半选**态，文案「已选 n / N」，不会与结果区脱节 |
| 再点「全选」 | 重新全勾 |
| 取消「全选」 | 全部清空，文案回「全选 N 套」；清空检索词后开关重新禁用 |

**一键批量提交**：全选后在任一输入框敲 **回车**，或直接点底部的「提交出库 / 提交回库」即可。
提交语义与逐套勾选完全一致 —— **一次提交多套、每套各出/回库 1 件**，共用同一组
经办人 / 领用人 / 时间 / 用途 / 备注，每套各生成一条流水。

> ⚠️ 刷卡严格校验（两人必刷、必须已登记且启用、角色匹配、不能同卡）**不受影响**：
> 「全选」只省去逐个勾选的动作，不降低记录的可追溯性。

## 状态机

```
                  出库 out              回库 return
  stocked(在库) ──────────→ checked_out(已出库) ──────────→ stocked
       │                                                       ↑
       │ 送修 repair                          维修完成 repair_done
       ↓                                                       │
    repair(维修中) ────────────────────────────────────────────┘
       │
       │ 报废 retire
       ↓
   retired(已报废) ── 终结状态 ──
```

流水类型与状态迁移对照：

| type | from → to | 说明 |
| --- | --- | --- |
| `out` | stocked → checked_out | 出库计数 +1 |
| `return` | checked_out → stocked | 回库计数 +1 |
| `repair` | stocked/checked_out → repair | 维修计数 +1 |
| `repair_done` | repair → stocked | 维修完成回库 |
| `retire` | 任意非 retired → retired | 终态 |

### 使用步骤
1. 点「📄 下载模板」拿到 `夹具导入模板.csv`（含示例行），或直接用你自己的表格。

### 容错设计（不必为了迁就程序去改表格）
- **列顺序任意**：程序按表头名字找列，不靠列位置；多余列自动忽略。
- **表头别名**：`夹具编号`/`实物编号`/`实物夹具编号`/`资产编号`/`serialno` → 夹具编号；`夹具名称`/`品名` → 名称；`类别` → 分类；`存放位置`/`位置`/`货位` → 库位；`产线1`/`线体1`/`产线一`（同理 2~5）→ 第 N 条产线；`产线`/`线体`/`产线名称`（旧版单列）→ 产线（一格可写多条，用分隔符隔开）；`适用机种`/`机型` → 机种。表头里的括号注释（`名称(必填)`）和冒号后缀会自动剥离。
- **旧模板仍可导入**：只给「产线」一列时按分隔符（`,` `，` `;` `；` `/` `、`）拆成多条产线；
  **旧模板里的「工位」「工位N」列会被静默忽略**——不报错、不写库，其余列照常生效。
- **机种两种写法**：给「机种名称1~12」十二个独立列，或只给一列「机种名称」内用逗号/分号分隔多个（`MODEL-A,MODEL-B;MODEL-C`）；自动去重，最多保留 **12** 个。
- **必填校验**（任一不满足即跳过该行并列明原因）：**名称为空 / 夹具编号为空或含竖线 / 库位不是 4 段式（如 `ZP1-U-1-1`）/ 机种名称为空 / 产线为空 / 超过 5 条产线**。
- **产线若未建档**：导入时按名称**自动补建**（同名复用、不重复创建），无需先去「产线配置」建档；预览会提示将自动新建哪些产线。
- **序号不由表格提供**：一律由系统自动分配（4 位纯数字，优先填补空洞），预览与卡片上都能看到。
- **重号提示**：夹具编号允许重复（同一机种多套），若该夹具编号已存在，预览中标注「(重号)」并提示已有多少套，但**不拦截**。

### 重复导入保护（v4.4.0）

同一份表连续导入两次，**不会再让记录翻倍**。

预览顶部会显示：`本次 N 行中，有 M 行与库内已有记录完全一致`，表格「状态」列逐行标注 **重复 / 新增**。
「完全一致」的判定口径是 **夹具编号 + 名称 + 库位 + 分类 + 机种集合 + 产线集合 + 备注** 全部相同，然后：

| 按钮 | 行为 | 什么时候用 |
| --- | --- | --- |
| **跳过重复，导入 N−M 条**（默认） | 只导入新增行 | 同一份表**误导了两次** |
| **全部导入 N 条** | 连重复行一起写入 | 确实**又买了 / 又做了**同号同库位的实物 |

> ⚠️ 判定只跟**库内已有记录**比，且是**多重集 1:1 配对**（库内 1 套 + 本次 2 行 → 1 重复 + 1 新增）。
> **不做批次内去重**：同一个库位放 2 套同号夹具是合法业务（真实台账里这类行有 236 组 / 578 行），
> 若按行去重会把这些真实数据直接吞掉。

导入完成后会弹出**结果窗口**（不是一闪而过的提示），列出「新增 / 失败 / 跳过重复 / 按选择跳过」，
并给 **「↩ 撤销本次导入 N 条」** —— 按批次号精确删除这一批（连带清理其流水），
**不影响此前导入或手工建档的记录**。关掉窗口后该按钮失效，只能逐条删除。

### 整份表都导不进去时

不再只弹一句「没有可导入的有效数据行」，而是弹窗列出**跳过原因统计**（如「产线为空 2189 行」「库位不合规 538 行」）
与前 10 条明细（行号 + 原因），便于回原表定点修数据。
最常见的原因是**产线列为空** —— 建档要求至少 1 条产线。


### 格式边界（明确不支持的情况）
| 格式 | 支持 | 说明 |
| --- | --- | --- |
| `.xlsx` | ✅ | Excel 工作簿，默认读取**第 1 张**工作表；多表会提示已选表名 |
| `.csv` | ✅ | UTF-8（含 BOM），支持引号转义与单元格内换行 |
| `.xls` | ❌ | 旧二进制格式，请先在 Excel 里另存为 `.xlsx` |

其他限制：不支持加密工作簿；公式只取 Excel 已缓存的计算结果（不重算）；日期列会以 Excel 序列号数字导入（当前字段无需日期）。

### 实现要点
- **零第三方依赖**：主进程内置 `js/xlsx_reader.js` 极简解析器，自行解 ZIP（`zlib.inflateRawSync`）并解析 `sharedStrings.xml` / `sheetN.xml`，支持共享字符串、`inlineStr`、数值、稀疏列自动补位、XML 实体解码。
- **为何放主进程**：渲染进程 `nodeIntegration:false` 取不到 `zlib`，故渲染进程传文件字节流、主进程解析后返回二维数组（IPC 通道 `pick-spreadsheet` / `read-spreadsheet`）。
- **复用既有数据层**：导入走 `DB.fixtureAdd()`，沿用既有校验（≥1 条产线且 ≤5 条、机种 ≤12、库位 4 段式、夹具编号合法）与序号自动分配逻辑；**未新增任何数据字段**。

- **与标签打印互斥**：打印清单会先清空二维码标签的打印区，反之亦然，不会两张纸互相串内容。


> v5.0.0 删除了 `stations` 集合与夹具上的 `stations` 字段；旧文件打开时自动清理。
> v5.1.0 新增 `staffs` 集合；旧文件打开时补成空数组（**刷卡功能需要先登记卡片才能用**）。

夹具记录的关键字段：

| 字段 | 含义 |
| --- | --- |
| `code` | **序号**：4 位纯数字、唯一、系统自动分配、**不可修改**（改则断流水与关联）；二维码内容；**不参与模糊搜索** |
| `serialNo` | **夹具编号**：手动输入、**可重复**（同一机种多套共用）、**主搜索键**；标签卡打印的就是它 |
| `lines` | 关联的产线 id 数组（≥1、上限 5） |
| `lineModels` | 机种名称数组（≤12） |
| `location` | 库位（4 段式，如 `ZP1-U-1-1`）。**出库冻结**，**回库可改**并写入流水 |
| `status` | `stocked` / `checked_out` / `repair` / `retired` |
| ~~`qrToken`~~ | v4 起**不再落库**，改为渲染时由 `code` 现场派生 |
| ~~`stations`~~ | **v5.0.0 起不再落库**，入库时若有该字段会被静默丢弃 |

人员卡记录（`staffs`，v5.1.0）的字段：

| 字段 | 含义 / 约束 |
| --- | --- |
| `cardNo` | **卡号**：读卡器读出的原始串（≤64 字符，禁 `|` 与逗号）。**归一化后必须唯一**（去空格 / `-` / `_`、转大写后比对）；落库存原样 |
| `name` | **姓名**：≤30 字符，禁 `|` 与换行；刷卡后显示的就是它 |
| `dept` | 部门（≤30 字符，可空） |
| `role` | `borrower`（领用人）/ `operator`（经办人，v5.6.0 起为历史角色）/ `both`（两者皆可，默认）；**不再参与刷卡校验** |
| `active` | `true` 启用 / `false` 停用。**停用后不能刷卡，但历史流水与台账保留** |
| `remark` | 备注（可空） |

流水的两个新字段：`partyCard`（领用/退库方**归一化卡号**）、`operatorCard`（经办方**归一化卡号**）；
同时 `counterparty` / `operator` 存的是**当时的姓名快照**，因此删人 / 改名都不会让历史流水断链。

**「数量」不是存储字段**：在库套数 = 按「夹具编号 + 库位」分组后、状态为 `stocked` 的记录条数。出库只把该套的 `status` 改成 `checked_out`，派生数量自然 −1；因此**不存在一个可被改错的「台账数量」字段**。

### 从旧版本升级（v3.0.1 / v4.x / v5.0.0 → v5.1.0）

## 使用方法（exe）

1. 将 `工装夹具管理程序.exe` 复制到你常用的任意位置（如桌面或 `D:\工具\`）。
2. **双击运行**即可，无需安装。首次启动为 1280×820 窗口，标题「工装夹具管理程序」（版本号只在页脚）。
3. **首次使用顺序建议**：先去「⚙️ 产线配置」建好线体 → 再到「夹具管理」点击 **新建夹具**，填写**夹具编号**、名称、机种（≤12）、库位，并在「关联产线」里**选产线 → 点「+ 添加」**（≥1 条、≤5 条；序号由系统分配，不用手填）。
4. 日常通过「出库管理 / 回库管理」登记业务，状态自动变化；「流水记录」追溯历史并导出。
5. 仪表盘顶部会显示夹具统计与最近动态，确认系统已正常启动。
6. 需要检索某夹具当前位置/状态时，用「🔎 夹具查询」多条件筛选，结果可直接「定位到库位」。
7. 想看「这条产线上装了哪些夹具」用「🔗 产线使用」；想看「用这个机种的夹具都在哪些线体」用「🏷 机种管理」—— 点机种名称即在下方展开明细。

## 常见问题

- **启动后空白 / 点不了？** 正常不会。若异常，请将窗口内显示的红色错误提示发我；该程序已做全局兜底，任何 JS 错误都会显式渲染到页面而非白屏。
- **为什么新建夹具时提示「请至少选择 1 条产线」？** 强校验要求：一件夹具必须至少关联 **1 条产线**（上限 5 条）。请先到「⚙️ 产线配置」建好线体。**v5.0.0 起不再要求工位**。
- **v5.0.0 之前的「工位」数据去哪了？** 首启迁移时会被**清除**（`data.stations` 集合与每条夹具的 `stations` 字段），夹具与流水不受影响。这是本次 MAJOR 升级的既定代价：产线 → 工位 → 夹具的三层结构简化为「夹具 ↔ 产线」两层。
- **序号能自己填吗？** 不能。它是系统分配的 4 位唯一数字（二维码内容、流水外键），**填写框已取消**；标签上印的是**夹具编号**。旧数据里已存在的编号会原样保留。
- **编号框里输入 `20-01`、`20_02`、`2003` 能搜到吗？** 能。搜索做了归一化容错（忽略大小写/连字符/下划线/空格；早前标签的二维码前缀 `SPMS1|` / `SPMS|` 也会被剥离）。但**序号不参与模糊搜索**，必须完整输入 4 位。
- **v4.0.0 打开后旧夹具的「规格型号」去哪了？** v2.1 起字段升级为「机种名称」，v4 首启会把旧 `spec` / `lineNo` 合并进 `lineModels`（上限放宽到 7），原数据不丢失。
- **导入 CSV 中文乱码？** 用 Excel 另存为 CSV（UTF-8）后导入；系统导出已带 UTF-8 BOM，Excel 可直接打开。
- **想多人共享 / 集中管理？** 当前为单机桌面版。如需多人集中访问，需要改为带后端（如 Node + 数据库）的版本。
- **数据存在哪、怎么备份？** 见上文「数据说明」。推荐定期在「数据备份」导出 JSON，或直接复制 `fixture-data.json`。
- **夹具查询的「责任人 / 借用人」怎么来的？** 不单独存字段：已出库取最近 `out` 流水的 `counterparty`；其余状态取最近流水的 `operator`；位置与最近操作时间同理由流水派生。
- **刷卡没反应 / 刷完没变成姓名？** 三种常见原因：① **光标不在刷卡框里** —— 读卡器等于键盘，先点一下那个框再刷；② **卡号没在「👤 人员卡库」登记** —— 刷完红字会写「未登记」，去卡库补登记即可；③ **卡片被停用** —— 红字会写「已停用（姓名）」。读卡器认不出时，可以**手工敲卡号 + 回车**，效果完全等同刷卡。
- **为什么现在只刷一张卡了？**（v5.6.0）现场一次出入库通常只有一个人在操作，第二个「经办人」刷卡位没有实际复核价值，反而拖慢节奏。改为单人刷卡后，责任主体由**领用人 / 退库人**承担，审计靠卡号快照追溯。
- **员工离职了，卡要走删除还是停用？** **停用**。停用后不能再刷，但人员台账和历史流水都保留；删除只用于「当初录错卡号」这种情形。两种情况历史流水的姓名与卡号快照都不会丢。
- **打印清单和屏幕对不上？** 不会 —— 两者调用**同一个取数函数**，屏幕上几套纸上就几套。若怀疑不一致，请确认打印时**没有中途改筛选条件**（改了会立刻重绘屏幕，但印出来的是点按钮那一刻的内容，属预期）。跨页时表头会自动重复，无需担心第二页看不懂列名。

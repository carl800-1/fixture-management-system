# 工装夹具管理程序 v4.0.1（桌面版 / 独立 exe）

**v4.0.1 是一个打包好的桌面程序**（基于 Electron）。双击 `工装夹具管理程序.exe` 即可使用，**无需安装、无需联网、无需浏览器**，所有数据保存在本机文件里。

> 系统覆盖夹具从建档、出库、回库、送修、维修完成到报废的全生命周期管理，并支持二维码标签、扫码作业、流水追溯与数据备份。
>
> **v4.0.0 是一次 MAJOR 升级**：数据模型从「按编号的台账」改为 **「每套一条记录」的追踪模型** ——
> **夹具编号**（如 `DH40MC-921-001-001`，可重复、手动输入、主搜索键）与系统自动分配的
> **序号**（4 位纯数字、唯一、二维码内容、不参与模糊搜索）分离；**数量不再存储，而是按
> 「夹具编号 + 库位」实时派生**；「夹具 ↔ 产线 / 工位」改为夹具记录上的扁平关联字段。
> 升级细节见 `修改日志.md` 的 v4.0.0 条目；已知问题、待确认事项与环境限制见 `问题清单.md`。
>
> **v4.0.1（PATCH）**：显示层术语统一 —— `实物编号`→`夹具编号`、`桥梁编号/桥梁号`→`序号`（底层字段 `serialNo` / `code` 不变，旧模板表头仍可导入）；夹具批量导入不再因产线/工位未建档而整表跳过，改为**按名称自动补建**（同名复用）。

## 二维码功能（离线）

系统已内置二维码**生成**（`qrcode-generator`）与**解码**（`jsQR`）库到 `js/vendor/`，**完全离线、无需联网**。

- **编码规范**：二维码只承载**序号**，格式 `SPMS1|<序号>`（如 `SPMS1|1001`）。该 token 是**派生值**（由 `code` 现场计算），**不落库**，避免与编号不一致的脏数据；名称 / 夹具编号等由系统按编号实时查库补全（原因：纯 ASCII 扫描最稳、码更小、且改名不影响旧码）。
- **标签卡内容**：只打印 **夹具编号 + 夹具名称** 两项（v4.0.0 起移除机种与库位，让标签更简洁、字号更醒目）。取舍：码磨损后需重新打印（可在「夹具管理」里按编号查回后重印）。
- **生成标签**：「夹具管理」每行「二维码」可预览/下载单张 PNG；顶部「批量打印标签」可一次性生成全部在库夹具的标签（二维码 + 编号 / 名称 / 机种名称 / 库位文字），用系统打印到标签纸。
- **扫码作业**：「出库 / 回库」均提供扫码入口，识别后自动选中对应夹具，后续录入流程不变。
  - **上传图片识别**：对标签拍照后上传即可识别，**离线可用**，是 exe 内的主用方式。
  - **摄像头实时扫码**：受桌面环境安全上下文限制，exe 内默认隐藏摄像头入口、仅保留上传图片，不影响作业。

## 状态机

```
                  出库 out              回库 return
  stocked(在库) ──────────→ checked_out(已出库) ──────────→ stocked
       │                                                       ↑
       │ 送修 repair                          维修完成 repair_done
       ↓                                                       │
    repair(维修中) ────────────────────────────────────────────┘
       │
       │ 报废 retire
       ↓
   retired(已报废) ── 终结状态 ──
```

流水类型与状态迁移对照：

| type | from → to | 说明 |
| --- | --- | --- |
| `out` | stocked → checked_out | 出库计数 +1 |
| `return` | checked_out → stocked | 回库计数 +1 |
| `repair` | stocked/checked_out → repair | 维修计数 +1 |
| `repair_done` | repair → stocked | 维修完成回库 |
| `retire` | 任意非 retired → retired | 终态 |

## Excel / CSV 批量导入（v2.3 新增，v4.0.0 表头扩充）

「夹具管理」页顶部有 **「⬆ 导入Excel/CSV」** 与 **「📄 下载模板」**，用于一次性录入成百上千条夹具，替代逐条「➕ 新建夹具」。

### 表头（14 列）

| 夹具编号 | 名称 | 机种名称1 | 机种名称2 | … | 机种名称7 | 分类 | 库位 | 产线 | 工位 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

### 使用步骤
1. 点「📄 下载模板」拿到 `夹具导入模板.csv`（含示例行），或直接用你自己的表格。
2. 按模板列填好：**夹具编号 / 名称 / 机种名称1~7 / 分类 / 库位 / 产线 / 工位 / 备注**。
3. 点「⬆ 导入Excel/CSV」→ 选择 `.xlsx` 或 `.csv` 文件。
4. **弹出预览表格**（最多展示 60 行），核对无误后点「确认导入 N 条」。

### 容错设计（不必为了迁就程序去改表格）
- **列顺序任意**：程序按表头名字找列，不靠列位置；多余列自动忽略。
- **表头别名**：`夹具编号`/`实物夹具编号`/`资产编号`/`serialno` → 夹具编号；`夹具名称`/`品名` → 名称；`类别` → 分类；`存放位置`/`位置`/`货位` → 库位；`线体`/`产线名称` → 产线；`工位名称`/`工位号` → 工位；`适用机种`/`机型` → 机种。表头里的括号注释（`名称(必填)`）和冒号后缀会自动剥离。
- **机种两种写法**：给「机种名称1~7」七个独立列，或只给一列「机种名称」内用逗号/分号分隔多个（`MODEL-A,MODEL-B;MODEL-C`）；自动去重，最多保留 **7** 个。
- **必填校验**（任一不满足即跳过该行并列明原因）：**名称为空 / 夹具编号为空或含竖线 / 库位不是 4 段式（如 `ZP1-U-1-1`）/ 机种名称为空 / 产线为空 / 产线未建档 / 工位为空 / 工位不属于已选产线 / 超过 5 条产线 / 超过 10 个工位**。
- **产线与工位若未建档**：导入时按名称**自动补建**（同名复用、不重复创建），无需先去「产线配置」建档；预览会提示将自动新建的产线/工位数。
- **序号不由表格提供**：一律由系统自动分配（4 位纯数字，优先填补空洞），预览与卡片上都能看到。
- **重号提示**：夹具编号允许重复（同一机种多套），若该夹具编号已存在，预览中标注「(重号)」并提示已有多少套，但**不拦截**。


### 格式边界（明确不支持的情况）
| 格式 | 支持 | 说明 |
| --- | --- | --- |
| `.xlsx` | ✅ | Excel 工作簿，默认读取**第 1 张**工作表；多表会提示已选表名 |
| `.csv` | ✅ | UTF-8（含 BOM），支持引号转义与单元格内换行 |
| `.xls` | ❌ | 旧二进制格式，请先在 Excel 里另存为 `.xlsx` |

其他限制：不支持加密工作簿；公式只取 Excel 已缓存的计算结果（不重算）；日期列会以 Excel 序列号数字导入（当前字段无需日期）。

### 实现要点
- **零第三方依赖**：主进程内置 `js/xlsx_reader.js` 极简解析器，自行解 ZIP（`zlib.inflateRawSync`）并解析 `sharedStrings.xml` / `sheetN.xml`，支持共享字符串、`inlineStr`、数值、稀疏列自动补位、XML 实体解码。
- **为何放主进程**：渲染进程 `nodeIntegration:false` 取不到 `zlib`，故渲染进程传文件字节流、主进程解析后返回二维数组（IPC 通道 `pick-spreadsheet` / `read-spreadsheet`）。
- **复用既有数据层**：导入走 `DB.fixtureAdd()`，沿用既有校验（≥1 产线 ≥1 工位、机种 ≤7、库位 4 段式、夹具编号合法）与序号自动分配逻辑；**未新增任何数据字段**。

## 关联模型：夹具 ↔ 产线 / 工位 / 机种（v4.0.0 重构）

v4.0.0 把「关联」全部收敛到夹具记录上，只保留几条独立关系：

| 关系 | 承载字段 | 说明 |
| --- | --- | --- |
| 产线 ↔ 工位 | `stations.lineId` | 工位**必然属于唯一一条产线**；工位名可跨产线重名（3 号线与 5 号线都有「2 号工位」） |
| 夹具 ↔ 产线 | `fixtures.lines: [lineId]` | **≥1 条、≤5 条**（建档强校验） |
| 夹具 ↔ 工位 | `fixtures.stations: [stationId]` | **≥1 个、≤10 个**，且必须 ⊆ 已选产线各自的工位集合 |
| 夹具 ↔ 机种 | `fixtures.lineModels: [name]` | 机种**不隶属产线**，只作标签；最多 7 个，存名称字符串数组 |
| （辅助）产线 ↔ 机种 | — | **没有这张表**。「某产线在用哪些机种」由 产线 → 工位 → 夹具 → 机种 反查推导 |

- **v3 的两张表已整体删除**：`products`（产品隶属线体）、`stationFixtures`（工位×产品绑定表）都不复存在。
- **删父级 = 摘除关联，不删夹具**：删产线 → 连带删其工位，并从所有夹具的 `lines` / `stations` 里摘掉这些 id；删工位 → 从夹具的 `stations` 摘掉。夹具本身与流水**不会因删结构而消失**。
- **机种字典**（`productions{id,name,order}`）只作**候选词表**：建档时在**同一个输入框**里直接输入即可，下拉会给出字典候选，也可输入全新名称（此时成为「孤儿机种」，事后可一键补登）；**多个机种用 `/` 分隔**（`,` `，` `;` `；` `、` 亦可，与批量导入的分隔规则一致），自动去重、最多 7 个。改名会**批量写穿**所有夹具的 `lineModels`；仍被引用时**禁止删除**。

## 产线配置（侧边栏「⚙️ 产线配置」）

| 面板 | 内容 | 说明 |
| --- | --- | --- |
| ① 线体 | 选用、名称、**形态**（直线形 / U型）、工位数、关联夹具数、备注、操作 | 形态只有两种，决定示意图画法，手工指定 |
| ② 工位与夹具（只读关联） | 工位名称、顺序、该工位上的夹具（夹具编号 + 序号）、备注、操作 | 关联**只读**：要改夹具挂在哪个工位，去「夹具管理 → 编辑夹具」；行内「编辑夹具」可直接跳转 |

- 工位行点「编辑夹具」：该工位只有 1 套夹具时直接打开编辑弹窗；多套时先弹出选择表供挑选。
- **删除会级联摘除**：删线体 → 连带其工位，并从全部夹具上摘掉这些关联；删工位 → 只摘该工位。删除前弹确认并告知影响数量。

### 批量导入（Excel / CSV）

「产线配置」页顶部有「⬆ 导入Excel/CSV」与「📄 下载模板」。模板是一张**平坦表**（**6 列**），每行表示「把某套已建档的夹具挂到某条产线的某个工位」：

| 线体 | 线体形态 | 工位 | 工位顺序 | 夹具编号 | 备注 |
| --- | --- | --- | --- | --- | --- |
| L1 总装线 | 直线形 | 上料工位 | 10 | DH40MC-921-001-001 | |
| L1 总装线 | 直线形 | 压装工位 | 20 | XXK-D10VG-002 | |
| L2 U型线 | U型 | 工位一 | 10 | DH40MC-921-001-002 | |

- **「夹具编号」= 夹具编号**（不是序号）；按它匹配夹具记录，**必须已在「夹具管理」建档**（不会自动建夹具）。
- 该编号对应 **0 套** → 跳过并列原因「未建档」；对应 **>1 套** → 跳过并列原因「对应 N 套夹具，无法唯一定位」（请改为到夹具管理里直接编辑）。
- **线体 / 工位按名称自动补建**（同名直接复用不重复建），列顺序任意、表头支持别名（`产线`/`线体名称`、`形态`/`类型`、`工位号`、`顺序`/`序号`、`编号`/`夹具号`/`夹具编号`）。
- **写库是「追加 + 去重」**：只往夹具记录里追加产线与工位，**绝不覆盖原有内容**；已存在的关联计为「无新增，已忽略」。
- **上限拦截**：追加后超过 5 条产线 / 10 个工位 的行会被跳过并在预览里说明。
- **导入前弹预览**：列出将新建多少线体/工位（含名称）、追加多少条、跳过哪些行（含逐行原因），确认后才写库。
- **可撤销**：导入完成后弹窗里有「↩ 撤销本次导入」，精确摘除本次追加的产线/工位，并回收本次新建且已无人引用的结构项。
- 格式边界同夹具导入：支持 `.xlsx`（默认读第 1 张工作表）与 `.csv`；`.xls` 需先另存为 `.xlsx`。

## 产线夹具查询（侧边栏「🔗 产线夹具查询」）

回答一个具体问题：**「这条产线的每个工位上，现在装着哪几套夹具？」** 并把它画成产线示意图。

1. **筛选区**：只选**线体**（v4 已去掉「线体 → 产品」级联，因为机种不隶属产线）。
2. **工位夹具配置表（只读）**：按工位顺序升序列出全部工位，固定 7 列——**工位名称 / 工位顺序 / 夹具编号 / 序号 / 夹具名称 / 状态 / 备注**。
   - 一个工位多套夹具时分多行展示，工位列用 `rowspan` 合并；
   - **没有任何夹具的工位显示「—」「无」**（弱化色），一眼看出哪些工位空着；
   - 点**夹具名称**直接打开「编辑夹具」弹窗（改关联请走这里）；
   - 表下明确提示「本表为**只读**视图」。
3. **产线示意图**（表格下方的 SVG 图）：
   - **直线形**：工位按顺序横向排列，每行最多 6 个，超出自动折行并画出折返连线；
   - **U型**：工位沿「左侧竖边下行 → 底部横边右移 → 右侧竖边上行」排列，按三段实际长度等分，首末工位落在左右两个顶端；
   - 每个工位节点标注**顺序号 + 工位名称 + 徽标**（徽标显示**夹具编号**，无夹具编号时退回 `#序号`）；**有夹具的工位高亮**（实心蓝点），无配置的为空心灰点并标注「无」；右上角有图例。
4. **统计文案**：`<线体名> ｜ 工位 N 个，已装夹具 M 个，夹具 K 套（本线关联 X 套）`。
5. 页内提供「⚙ 去配置产线」与「🏷 按机种查询」跳转。

### 按机种查询（侧边栏「🧭 按机种查询」）

反向视角：**「用这个机种的夹具都落在哪些产线、放在哪个库位、现在什么状态？」**

- 机种下拉 = 机种字典 ∪ 夹具在用（孤儿机种也能查），默认「全部机种（按机种分组）」。
- 结果按**机种**分组（组头显示机种名与条数），固定列 **产线 / 夹具编号（夹具编号 + `#序号`）/ 库位 / 状态**。
- 夹具**没有关联任何产线**时，产线列显示占位「（未关联产线）」。
- 提醒：机种与产线之间**没有直接绑定**，这里的产线全部由夹具记录的产线字段反查得出。

### 状态处理

| 状态 | 表现 |
| --- | --- |
| 加载中 | 面板内显示转圈 + 「正在加载产线配置…」 |
| 未选线体 / 无线体 | 各自的空态提示，并引导去「产线配置」新建 |
| 线体下无工位 | 「线体「X」下还没有工位，请先到「产线配置」添加工位」 |
| 查询有结果 | 配置表 + 产线示意图 + 统计文案 |

### 数据存储

集合为 `lines` / `stations` / `productions`（**不再有 `products` / `stationFixtures`**），与夹具数据同存于 exe 同目录的 `fixture-data.json`，**不新增数据文件**；旧数据文件缺少某集合时按空数组处理。

## 夹具查询（v2.2 新增）

侧边栏「🔎 夹具查询」进入独立检索页，支持**多条件组合 + 关键字模糊**：

- **检索维度**：夹具编号、名称/规格、关联机种（lineModels 任一命中）、存放库位（下拉）、使用状态（在库/已出库/维修中/已报废 多选 chip）、借用人（由流水 `counterparty`/`operator` 派生），以及跨字段关键字模糊搜索。
- **结果展示**：表格列出编号、名称、当前位置（在库→库位；已出库→「外借·借用人」；维修中→库位+(维修中)；报废→已报废）、责任人、状态、最近操作时间；状态以红/绿 badge 区分；点击表头可排序。
- **交互**：「详情」弹窗看完整字段与最近流水；「定位到库位」一键跳转库位视图并预筛该夹具所在位；无结果时显式空状态提示；「重置筛选」清空全部条件。
- **实现要点**：位置/责任人/最近时间均由 `fixTransactions` 流水**派生**，不新增数据字段；排序操作对象引用数组，保证关联字段索引一致、不错位。

## 数据说明（重要）

- v4.0.1 的数据保存在 **exe 同目录**下的 `fixture-data.json`：

  ```
  D:\project\fixture\v4.0.1\fixture-data.json
  ```

- 该文件是普通 JSON，**可直接整文件复制备份**；也可在程序内「数据备份」中导出/导入业务数据 JSON。
- 卸载或换电脑时，记得先「数据备份」导出，再在另一台机器「导入备份恢复」。
- **运行期错误兜底**：任何 JS 错误都会显式渲染到页面上（不会白屏），把页面提示发回即可定位。

### 数据模型（v4.0.0）

```
{
  "fixtures":       [ 每套夹具一条记录，无 quantity 字段 ],
  "fixTransactions":[ 状态流转流水，含 fromLocation/toLocation 快照 ],
  "lines":          [ { id, name, type: 'linear'|'u', remark } ],
  "stations":       [ { id, lineId, seq, name, remark } ],
  "productions":    [ { id, name, order } ]        // 机种字典
}
```

夹具记录的关键字段：

| 字段 | 含义 |
| --- | --- |
| `code` | **序号**：4 位纯数字、唯一、系统自动分配、**不可修改**（改则断流水与关联）；二维码内容；**不参与模糊搜索** |
| `serialNo` | **夹具编号**：手动输入、**可重复**（同一机种多套共用）、**主搜索键**；标签卡打印的就是它 |
| `lines` / `stations` | 关联的产线 id / 工位 id 数组（≥1、上限 5 / 10） |
| `lineModels` | 机种名称数组（≤7） |
| `location` | 库位（4 段式，如 `ZP1-U-1-1`）。**出库冻结**，**回库可改**并写入流水 |
| `status` | `stocked` / `checked_out` / `repair` / `retired` |
| ~~`qrToken`~~ | v4 起**不再落库**，改为渲染时由 `code` 现场派生 |

**「数量」不是存储字段**：在库套数 = 按「夹具编号 + 库位」分组后、状态为 `stocked` 的记录条数。出库只把该套的 `status` 改成 `checked_out`，派生数量自然 −1；因此**不存在一个可被改错的「台账数量」字段**。

### 从 v3.0.1 升级

首次启动会自动迁移：`spec` + `lineNo` 合并进 `lineModels`（上限放宽到 7，不再截断到 4）；`products` 按名称去重转成 `productions{id,name,order}`；补齐 `lines` / `stations` / `serialNo` 空值；删除 `qrToken` 与 `stationFixtures`、`products` 集合。**旧 `fixture-data.json` 直接覆盖到新版本目录即可**，无需手工处理。

## 使用方法（exe）

1. 将 `工装夹具管理程序.exe` 复制到你常用的任意位置（如桌面或 `D:\工具\`）。
2. **双击运行**即可，无需安装。首次启动为 1280×820 窗口，标题「工装夹具管理程序 v4.0.1」。
3. **首次使用顺序建议**：先去「⚙️ 产线配置」建好线体与工位 → 再到「夹具管理」点击 **新建夹具**，填写**夹具编号**、名称、机种（≤7）、库位，并**至少勾选 1 条产线 + 1 个工位**（序号由系统分配，不用手填）。
4. 日常通过「出库管理 / 回库管理」登记业务，状态自动变化；「流水记录」追溯历史并导出。
5. 仪表盘顶部会显示夹具统计与最近动态，确认系统已正常启动。
6. 需要检索某夹具当前位置/状态时，用「🔎 夹具查询」多条件筛选，结果可直接「定位到库位」。
7. 想看「这条产线每个工位装了哪些夹具」用「🔗 产线夹具查询」；想看「用这个机种的夹具都在哪些产线」用「🧭 按机种查询」。

### 受限网络 / 本机构建说明

- **构建前必须清空 `NODE_OPTIONS`**：WorkBuddy 沙箱垫片会在构建收尾删除时卡死。
  ```bash
  export NODE_OPTIONS=
  export CODEBUDDY_SESSION_ID=
  export CLAUDE_SESSION_ID=
  unset ELECTRON_RUN_AS_NODE
  ```
- **Windows Search / Defender 可能锁文件**：构建到全新输出目录（如 `release_v21`）规避，不要复用被锁的 `release/win-unpacked/`；若 `electron-builder` 在 `unlink default_app.asar` 处报 EBUSY，可手动组装：克隆上一版目录后覆盖 `resources/app` 源码即可。
- **`asar: false`**：规避 asar 内路径分隔符问题。
- **`electronDist` 指向本地 Electron**，跳过联网下载。
- **CSS 必须位于 `css/style.css`**（`index.html` 引用路径），放根目录会导致程序无样式。

## 常见问题

- **v4.0.0 启动后空白 / 点不了？** 正常不会。若异常，请将窗口内显示的红色错误提示发我；该程序已做全局兜底，任何 JS 错误都会显式渲染到页面而非白屏。
- **为什么新建夹具时提示「请至少选择 1 条产线」？** v4.0.0 的强校验要求：一件夹具必须至少关联 **1 条产线 + 1 个工位**（上限 5 条 / 10 个）。请先到「⚙️ 产线配置」建好线体与工位。
- **序号能自己填吗？** 不能。它是系统分配的 4 位唯一数字（二维码内容、流水外键），**填写框已取消**；标签上印的是**夹具编号**。旧数据里已存在的编号会原样保留。
- **编号框里输入 `20-01`、`20_02`、`SPMS1|2003` 能搜到吗？** 能。搜索做了归一化容错（忽略大小写/连字符/下划线/空格、剥离二维码前缀）。但**序号不参与模糊搜索**，必须完整输入 4 位。
- **v4.0.0 打开后旧夹具的「规格型号」去哪了？** v2.1 起字段升级为「机种名称」，v4 首启会把旧 `spec` / `lineNo` 合并进 `lineModels`（上限放宽到 7），原数据不丢失。
- **导入 CSV 中文乱码？** 用 Excel 另存为 CSV（UTF-8）后导入；系统导出已带 UTF-8 BOM，Excel 可直接打开。
- **想多人共享 / 集中管理？** 当前为单机桌面版。如需多人集中访问，需要改为带后端（如 Node + 数据库）的版本。
- **数据存在哪、怎么备份？** 见上文「数据说明」。推荐定期在「数据备份」导出 JSON，或直接复制 `fixture-data.json`。
- **夹具查询的「责任人 / 借用人」怎么来的？** 不单独存字段：已出库取最近 `out` 流水的 `counterparty`；其余状态取最近流水的 `operator`；位置与最近操作时间同理由流水派生。

# 工装夹具管理程序 v3.0.1（桌面版 / 独立 exe）

**v3.0.1 是一个打包好的桌面程序**（基于 Electron）。双击 `工装夹具管理程序.exe` 即可使用，**无需安装、无需联网、无需浏览器**，所有数据保存在本机文件里。

> 系统覆盖夹具从建档、出库、回库、送修、维修完成到报废的全生命周期管理，并支持二维码标签、扫码作业、流水追溯与数据备份。

## 功能模块

| 模块 | 说明 |
| --- | --- |
| 仪表盘 | 夹具总数、在库 / 已出库 / 维修中 / 已报废统计；今日流水；最近动态 |
| 夹具管理 | 建档（4 位数字编号）、编辑、搜索、卡片/列表视图切换、CSV 导出；**v2.1 起支持关联最多 4 个机种名称**；**v2.3 起支持 Excel/CSV 批量导入** |
| 出库管理 | 编号 / 名称 / 机种名称 / 库位四栏互查 → 经办人 / 领用人 → 确认出库 |
| 回库管理 | 编号 / 名称 / 机种名称 / 库位四栏互查 → 经办人 → 确认回库 |
| 送修管理 | 在库或已出库夹具 → 选择维修类型（普通维修 / 校准 / 更换配件 / 保养）→ 确认送修 |
| 维修完成 | 维修中夹具 → 经办人确认 → 回库 |
| 报废管理 | 任意非报废夹具 → 填写报废原因 → 确认报废（终态，禁止再出库） |
| 库位管理 | 10 列网格库位总览、点击筛选夹具明细、手工盘点 CSV 导出 |
| 流水记录 | 完整状态流转轨迹，可按编号 / 名称 / 机种名称 / 经办人搜索 |
| 夹具查询 | 多条件组合检索：编号 / 名称 / 机种 / 库位 / 状态多选 / 借用人 + 关键字模糊；结果表含位置·责任人·状态·最近操作，支持详情弹窗与「定位到库位」 |
| 产线夹具查询 | 按「线体 + 产品」级联筛选，展示该产品在各工位使用的夹具（工位顺序/夹具编号/名称/规格，无配置显示「—」），下方以 SVG 绘制产线示意图（直线形/U型），高亮有夹具的工位 |
| 产线配置 | 维护线体（名称/形态/备注）、产品（隶属线体）、工位（名称/顺序）与工位夹具绑定（一对多）；支持 Excel/CSV 批量导入，删除父级自动级联清理 |
| 二维码标签 | 单夹具二维码预览/下载 PNG；单个/批量打印标签（纸张尺寸 / 对齐 / 边距 / 份数 + 实时预览） |
| 数据备份 | 导出全部数据为 JSON 备份；导入备份恢复；清空数据（危险） |

## 二维码功能（离线）

系统已内置二维码**生成**（`qrcode-generator`）与**解码**（`jsQR`）库到 `js/vendor/`，**完全离线、无需联网**。

- **编码规范**：二维码只承载夹具唯一编号，格式 `SPMS1|<编号>`（如 `SPMS1|2001`）。名称 / 机种名称等由系统按编号实时查库补全（原因：纯 ASCII 扫描最稳、码更小、且更名不影响旧码）。
- **生成标签**：「夹具管理」每行「二维码」可预览/下载单张 PNG；顶部「批量打印标签」可一次性生成全部在库夹具的标签（二维码 + 编号 / 名称 / 机种名称 / 库位文字），用系统打印到标签纸。
- **扫码作业**：「出库 / 回库」均提供扫码入口，识别后自动选中对应夹具，后续录入流程不变。
  - **上传图片识别**：对标签拍照后上传即可识别，**离线可用**，是 exe 内的主用方式。
  - **摄像头实时扫码**：受桌面环境安全上下文限制，exe 内默认隐藏摄像头入口、仅保留上传图片，不影响作业。

## 状态机

```
                  出库 out              回库 return
  stocked(在库) ──────────→ checked_out(已出库) ──────────→ stocked
       │                                                       ↑
       │ 送修 repair                          维修完成 repair_done
       ↓                                                       │
    repair(维修中) ────────────────────────────────────────────┘
       │
       │ 报废 retire
       ↓
   retired(已报废) ── 终结状态 ──
```

流水类型与状态迁移对照：

| type | from → to | 说明 |
| --- | --- | --- |
| `out` | stocked → checked_out | 出库计数 +1 |
| `return` | checked_out → stocked | 回库计数 +1 |
| `repair` | stocked/checked_out → repair | 维修计数 +1 |
| `repair_done` | repair → stocked | 维修完成回库 |
| `retire` | 任意非 retired → retired | 终态 |

## Excel / CSV 批量导入（v2.3 新增）

「夹具管理」页顶部新增 **「⬆ 导入Excel/CSV」** 与 **「📄 下载模板」**，用于一次性录入成百上千条夹具，替代逐条「➕ 新建夹具」。

### 使用步骤
1. 点「📄 下载模板」拿到 `夹具导入模板.csv`（含 2 行示例），或直接用你自己的表格。
2. 按模板列填好：编号、名称、机种名称1~4、分类、库位、备注。
3. 点「⬆ 导入Excel/CSV」→ 选择 `.xlsx` 或 `.csv` 文件。
4. **弹出预览表格**（最多展示 60 行），核对无误后点「确认导入 N 条」。

### 容错设计（不必为了迁就程序去改表格）
- **列顺序任意**：程序按表头名字找列，不靠列位置；多余列自动忽略。
- **表头别名**：`编码`/`夹具编号`/`序号` → 编号；`夹具名称`/`品名` → 名称；`类别` → 分类；`存放位置`/`位置`/`货位` → 库位；`适用机种`/`机型` → 机种名称。表头里的括号注释（`名称(必填)`）和冒号后缀会自动剥离。
- **编号自动分配**：编号为空、非 4 位纯数字、或与已有重复时，系统自动分配下一个空闲 4 位号（优先填补编号空洞），预览表中标注 `(自动)` 便于核对——**不会因为编号问题丢数据**。
- **机种两种写法**：给「机种名称1~4」四个独立列，或只给一列「机种名称」内用逗号/分号分隔多个（`MODEL-A,MODEL-B;MODEL-C`）；自动去重，最多保留 4 个。
- **名称为空**的行会被跳过，并在预览顶部提示跳过条数与行号。

### 格式边界（明确不支持的情况）
| 格式 | 支持 | 说明 |
| --- | --- | --- |
| `.xlsx` | ✅ | Excel 工作簿，默认读取**第 1 张**工作表；多表会提示已选表名 |
| `.csv` | ✅ | UTF-8（含 BOM），支持引号转义与单元格内换行 |
| `.xls` | ❌ | 旧二进制格式，请先在 Excel 里另存为 `.xlsx` |

其他限制：不支持加密工作簿；公式只取 Excel 已缓存的计算结果（不重算）；日期列会以 Excel 序列号数字导入（当前字段无需日期）。

### 实现要点
- **零第三方依赖**：主进程内置 `js/xlsx_reader.js` 极简解析器，自行解 ZIP（`zlib.inflateRawSync`）并解析 `sharedStrings.xml` / `sheetN.xml`，支持共享字符串、`inlineStr`、数值、稀疏列自动补位、XML 实体解码。
- **为何放主进程**：渲染进程 `nodeIntegration:false` 取不到 `zlib`，故渲染进程传文件字节流、主进程解析后返回二维数组（IPC 通道 `pick-spreadsheet` / `read-spreadsheet`）。
- **复用既有数据层**：导入走 `DB.fixtureAdd()`，沿用现有限号唯一校验与 `qrToken` 生成逻辑，**未新增任何数据字段**。

## 产线夹具查询 / 产线配置（v3.0.1 新增）

用于回答一个具体问题：**「这个产品在这条产线上，每个工位该用哪几套夹具？」** 并把它画成产线示意图。

### 一、产线配置（侧边栏「⚙️ 产线配置」）

数据层级：**线体** →（**产品** / **工位**），夹具绑定挂在「产品 × 工位」上。

| 面板 | 内容 | 说明 |
| --- | --- | --- |
| ① 线体 | 名称、**形态**（直线形 / U型）、备注 | 形态只有两种，决定查询页示意图的画法，手工指定 |
| ② 产品 | 名称、编号、备注 | 隶属选中的线体 |
| ③ 工位与夹具配置 | 工位名称、**顺序**、该产品在此工位使用的夹具编号、备注 | 点「配置夹具」为选中产品绑定编号 |

- **工位夹具是一对多**：一个工位可以绑多个夹具编号。输入框里一行一个，或用逗号/顿号/分号分隔，重复自动去重；**留空保存即清空**该工位配置。
- **删除会级联**：删线体 → 连带其产品、工位与全部绑定；删产品/工位 → 连带其绑定。删除前会弹确认并告诉你将影响多少条数据。

### 二、批量导入（Excel / CSV）

「产线配置」页顶部有「⬆ 导入Excel/CSV」与「📄 下载模板」。模板是一张**平坦表**，每行表示「某线体下某产品在某工位使用的一个夹具」：

| 线体 | 线体形态 | 产品 | 产品编号 | 工位 | 工位顺序 | 夹具编号 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| L1 总装线 | 直线形 | 产品甲 | P-01 | 上料工位 | 10 | 2001 | |
| L1 总装线 | 直线形 | 产品甲 | P-01 | 压装工位 | 20 | 2002 | |
| L1 总装线 | 直线形 | 产品甲 | P-01 | 压装工位 | 20 | 2003 | 同工位多个夹具 |
| L1 总装线 | 直线形 | 产品甲 | P-01 | 检测工位 | 30 | | 该工位暂无夹具 |

- **按名称自动补建**：线体/产品/工位若不存在会自动创建，**同名直接复用不重复建**。
- **导入前弹预览**：会列出将新建多少线体/产品/工位（含名称）、绑定多少条、跳过哪些行，确认后才写库。
- **幂等**：同一份文件重复导入，结果完全一致，不会产生重复数据。
- **夹具编号为空**的行只建结构不绑定，对应「该工位暂无夹具」的场景。
- 表头支持别名（`产线`/`线体名称`、`形态`/`类型`、`机型`/`机种`、`工位号`、`顺序`/`序号`、`编号`/`夹具`），列顺序任意、多余列自动忽略。
- 格式边界同夹具导入：支持 `.xlsx`（默认读第 1 张工作表）与 `.csv`；`.xls` 需先另存为 `.xlsx`。

### 三、产线夹具查询（侧边栏「🔗 产线夹具查询」）

1. **筛选区**：选线体 → 选产品。二者是**级联**关系——切换线体会立即重置并按新线体重建产品下拉，不会残留上一个线体的产品。
2. **工位夹具配置表**：按工位顺序升序列出全部工位，字段为工位名称、工位顺序、夹具编号、夹具名称、规格/型号、备注。
   - 一个工位多个夹具时，夹具信息分多行展示，工位列合并显示；
   - **没有任何夹具的工位显示「—」「无」**（弱化色），一眼看出哪些工位没配。
   - 夹具编号在夹具库中不存在时标为「编号未建档」，并在表下统计数量。
3. **产线示意图**（表格下方的 SVG 图）：
   - **直线形**：工位按顺序横向排列，每行最多 6 个，超出自动折行并画出折返连线；
   - **U型**：工位沿「左侧竖边下行 → 底部横边右移 → 右侧竖边上行」排列，按三段实际长度等分，首末工位落在左右两个顶端；
   - 每个工位节点标注**顺序号 + 工位名称 + 夹具编号**；**有夹具配置的工位高亮**（实心蓝点），无配置的为空心灰点并标注「无」；右上角有图例。

### 状态处理

| 状态 | 表现 |
| --- | --- |
| 加载中 | 面板内显示转圈 + 「正在加载产线配置…」 |
| 未选线体 / 无产品 / 无线体 | 各自的空态提示，并引导去「产线配置」新建 |
| 线体下无工位 | 「线体「X」下还没有工位…」 |
| 查询有结果 | 表格 + 产线示意图，标题栏显示「工位 N 个，已配置 M 个，夹具 K 件」 |

### 数据存储

四个新集合 `lines` / `products` / `stations` / `stationFixtures` 与其他数据同存于 exe 同目录的 `fixture-data.json`，**不新增数据文件**；旧数据文件缺少这些集合时按空数组处理，无需迁移。

## 夹具查询（v2.2 新增）

侧边栏「🔎 夹具查询」进入独立检索页，支持**多条件组合 + 关键字模糊**：

- **检索维度**：夹具编号、名称/规格、关联机种（lineModels 任一命中）、存放库位（下拉）、使用状态（在库/已出库/维修中/已报废 多选 chip）、借用人（由流水 `counterparty`/`operator` 派生），以及跨字段关键字模糊搜索。
- **结果展示**：表格列出编号、名称、当前位置（在库→库位；已出库→「外借·借用人」；维修中→库位+(维修中)；报废→已报废）、责任人、状态、最近操作时间；状态以红/绿 badge 区分；点击表头可排序。
- **交互**：「详情」弹窗看完整字段与最近流水；「定位到库位」一键跳转库位视图并预筛该夹具所在位；无结果时显式空状态提示；「重置筛选」清空全部条件。
- **实现要点**：位置/责任人/最近时间均由 `fixTransactions` 流水**派生**，不新增数据字段；排序操作对象引用数组，保证关联字段索引一致、不错位。

## 使用方法（exe）

1. 将 `工装夹具管理程序.exe` 复制到你常用的任意位置（如桌面或 `D:\工具\`）。
2. **双击运行**即可，无需安装。首次启动为 1280×820 窗口，标题「工装夹具管理程序 v3.0.1」。
3. 首次使用建议：在「夹具管理」点击 **新建夹具**，录入编号、名称及 1~4 个机种名称。
4. 日常通过「出库管理 / 回库管理」登记业务，状态自动变化；「流水记录」追溯历史并导出。
5. 仪表盘顶部会显示夹具统计与最近动态，确认系统已正常启动。
6. 需要检索某夹具当前位置/状态时，用「🔎 夹具查询」多条件筛选，结果可直接「定位到库位」。

## 本地构建（开发/二次打包）

需要 Node.js 18+ 与 npm。在源码目录执行：

```bash
cd fixtures/v1.0

# 1) 安装依赖
npm install

# 2) 开发调试
npm start

# 3) 打包为独立 exe（产物在 release_v21/）
npm run build
```

构建完成后在 `release_v21/win-unpacked/` 得到完整程序目录，可重命名为 `v<版本号>` 使用。

### 受限网络 / 本机构建说明

- **构建前必须清空 `NODE_OPTIONS`**：WorkBuddy 沙箱垫片会在构建收尾删除时卡死。
  ```bash
  export NODE_OPTIONS=
  export CODEBUDDY_SESSION_ID=
  export CLAUDE_SESSION_ID=
  unset ELECTRON_RUN_AS_NODE
  ```
- **Windows Search / Defender 可能锁文件**：构建到全新输出目录（如 `release_v21`）规避，不要复用被锁的 `release/win-unpacked/`；若 `electron-builder` 在 `unlink default_app.asar` 处报 EBUSY，可手动组装：克隆上一版目录后覆盖 `resources/app` 源码即可。
- **`asar: false`**：规避 asar 内路径分隔符问题。
- **`electronDist` 指向本地 Electron**，跳过联网下载。
- **CSS 必须位于 `css/style.css`**（`index.html` 引用路径），放根目录会导致程序无样式。

## 发布目录

输出根目录固定为 **`D:\project\fixture`**，每个版本一个子文件夹：

```
D:\project\fixture\
├── v3.0.1\                 ← 版本子文件夹（以版本号命名）
│   ├── 工装夹具管理程序.exe    ← 双击直接运行
│   ├── *.dll / locales\ / resources\ ...
│   └── fixture-data.json             ← 运行后自动生成，数据同目录落盘
└── v1.9\  v2.0\  v2.1\ ...          ← 旧版本保留可回滚
```

发布步骤（升版时）：
1. 改源码 + 同步版本号标记（见 `修改日志.md` 顶部规则）。
2. 构建后 `D:\project\fixture\` 下会生成 `win-unpacked`。
3. 将 `win-unpacked` **重命名**为 `v<语义化版本号>`（如 `v3.0.1`）。
4. 若需保留旧数据，把上一版本的 `fixture-data.json` 复制进新版本目录。

## 常见问题

- **v3.0.1 启动后空白 / 点不了？** 正常不会。若异常，请将窗口内显示的红色错误提示发我；该程序已做全局兜底，任何 JS 错误都会显式渲染到页面而非白屏。
- **v3.0.1 打开后旧夹具的「规格型号」去哪了？** v2.1 起字段升级为「机种名称」，旧 `spec` / `lineNo` 会在首次启动时自动迁移进 `lineModels`，原数据不丢失。
- **导入 CSV 中文乱码？** 用 Excel 另存为 CSV（UTF-8）后导入；系统导出已带 UTF-8 BOM，Excel 可直接打开。
- **想多人共享 / 集中管理？** 当前为单机桌面版。如需多人集中访问，需要改为带后端（如 Node + 数据库）的版本。
- **数据存在哪、怎么备份？** 见上文「数据说明」。推荐定期在「数据备份」导出 JSON，或直接复制 `fixture-data.json`。
- **夹具查询的「责任人 / 借用人」怎么来的？** 不单独存字段：已出库取最近 `out` 流水的 `counterparty`；其余状态取最近流水的 `operator`；位置与最近操作时间同理由流水派生。
